# HHY 1.2.0

HHY 1.2.0 establishes the first official-extension distribution path without changing frozen language semantics or Process Extension Protocol 1.

## Signed Registry

- Adds `namespace/name` package identities and an explicitly supplied Ed25519 trust root.
- Verifies the signed Registry index and each signed package descriptor.
- Binds identity, version, runtime name, dependencies, source, and every payload SHA-256 digest into signed metadata.
- Rejects duplicate coordinates, invalid identities, invalid signatures, and modified payloads before installation.

## Resolution and transaction safety

- Resolves exact, `>=`, caret, and wildcard constraints across transitive dependencies.
- Produces a deterministic, dependency-first plan and rejects cycles, missing versions, and conflicts.
- Adds `--dry-run`, which performs complete verification without changing the extension home.
- Stages local and Registry packages on the destination filesystem and commits each package by atomic rename.
- Rolls back packages added by the current dependency transaction if a later package fails, while preserving pre-existing packages.

## Scope

The v1.2.0 client consumes a static Registry snapshot and does not require a domain. Lockfiles, offline caches, explicit upgrades, and user-visible version rollback remain v1.2.1 work. No tag or GitHub Release is created for this development checkpoint.
