# HHY v1.3.0-rc (evaluation draft)

This is an RC evaluation record, not a release or lifecycle promotion. The
project remains `1.3.0-alpha`, and GitHub Actions/Release publication is deferred.

## Evaluation tooling implemented

- `hhy profile --engine ast|bytecode` reports the selected engine, HHY function
  names, source paths, lines, and columns.
- Structured Runtime errors now retain a bounded HHY call stack with source
  positions; AST and Bytecode paths produce identical stack values.
- `make benchmark-bytecode` measures both engines, Bytecode compilation, total
  wall time, binary size, platform, commit, and repeated samples.
- `scripts/check-bytecode-rc.py` produces a machine-readable default-engine
  decision and supports a strict `--require-ready` release gate.
- Test-only `HHY_TEST_BYTECODE_FAULT=invalid-opcode|missing-halt` injection proves
  malformed Bytecode fails closed with exit status 2 and a stable diagnostic.

## Current local decision

The first local arm64 macOS sample did not pass every reviewed performance gate.
The CPU-bound ratio was close to, but did not meet, the required gain, and the
JSON/I/O-oriented case exceeded the allowed regression ratio. AST therefore
remains the selected default. These measurements are development evidence only;
they are not cross-platform release evidence.

## Remaining RC gates

- Complete the dedicated opcode dispatch loop and full fixture conformance.
- Re-run stable, longer benchmarks after dispatch optimization.
- Pass Release, sanitizers, GC stress, fuzz, failure injection, Linux/macOS/
  Windows workflows, and at least one uninterrupted RC observation cycle.
- Publish nothing until the coordinated multi-version Actions/Release pass.
