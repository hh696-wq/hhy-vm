# HHY 公共路线图

更新日期：2026-09-09。当前产品为 1.7.0，语言规范为冻结的 1.0.0，Database 独立版本为 1.0.0。

## 已交付基线

| 阶段 | 交付与边界 |
| --- | --- |
| v1.1–v1.2 | 稳定性、诊断、进程扩展、签名分发、lock/离线/回滚与 HTML 验证 |
| v1.3 | 经验证的 Bytecode VM；1.3.5 起默认，AST 保留；缓存因收益不足未准入 |
| v1.4 | Web Runtime，统一通过 1.4.3 交付 |
| v1.5 | Database 1.0.0 与请求作用域、取消及 Worker 隔离 |
| v1.6–v1.7 | Runtime 实验和 Optimizing Compiler，统一通过 1.7.0 交付；新优化默认关闭 |

v1.3.3/v1.3.4 的能力可从 v1.3.5 说明核对，但未确认独立发行 tag/资产；
v1.4.0–1.4.2、v1.6.x、v1.7.1–1.7.3 是工程里程碑，不是独立安装包。
完整版本状态见[发行索引](https://github.com/hh696-wq/hhy-vm/releases)。

## 下一阶段：v1.8 外部采用

1. 固定可复现安装基线和官方模板，优先 CI 质量门禁与多 API 数据采集。
2. 完善已有 `hhy doctor extensions` 的诊断与恢复文档；`hhy init` 仍为规划。
3. 记录首次成功耗时、失败原因、平台和依赖；邀请 3–5 名非作者用户覆盖至少两个场景。
4. 至少一个案例运行一周或进入真实 CI，用户能独立部署；收集失败和放弃案例。
5. 按实际声明补齐 Web/DB 长稳与 RDS 实机证据，未验证范围继续明确保留。

模板和编辑器可独立维护，Core 留下可复现集成测试与协议契约。此路线不承诺发布日期。

## 条件研究

Compiler/Runtime 默认启用必须满足对应版本化预算，不能用合成提速替代真实收益。
Superinstruction、PIC、GC 替换和 async scheduler 尚未准入。
v2.0 的 Native ABI/FFI 决策至少需要两个真实集成证明进程协议不足；继续使用进程协议也是有效结论。

## 证据与维护

公开源码保存基准程序、预算策略、测试和审阅结论；原始报告由 CI artifacts 或独立归档管理。
性能记录注明版本/commit、平台、输入、样本和限制；历史数据不自动视为当前版本结果。
参见[Compiler IR](architecture/COMPILER_IR.md)、[已知限制](KNOWN_LIMITATIONS.md)和[贡献流程](../CONTRIBUTING.md)。
